# شرح المشروع: متتبع التقديمات (Job Application Tracker)

المشروع ده React app بسيط بيتتبع الوظايف اللي قدمت عليها: تضيف، تعدل، تمسح،
وتفلتر حسب الحالة. البيانات بتتحفظ في المتصفح نفسه (localStorage)، فمفيش
سيرفر ولا قاعدة بيانات دلوقتي، وده ممكن يتضاف بعدين.

## تشغيل المشروع على جهازك

```bash
npm install
npm run dev
```

هيطلعلك لينك في الترمينال (غالبًا http://localhost:5173) افتحه في المتصفح.

## شرح كل ملف

- **index.html**: صفحة الـ HTML الوحيدة. فيها بس `<div id="root">` اللي React
  بيرسم جواه كل حاجة.
- **src/main.jsx**: نقطة البداية. بيرندر مكون `<App />` جوا الـ div ده.
- **src/App.jsx**: قلب المشروع. فيه كل الحالة (state):
  - `applications`: قائمة التقديمات كلها.
  - `statusFilter`: الفلتر الحالي.
  - `editing`: التقديمة اللي بنعدل عليها دلوقتي (أو null لو بنضيف جديدة).
  - `useEffect` بيحفظ القائمة في localStorage كل ما تتغير.
  - وفيه دوال `addApplication` و`updateApplication` و`deleteApplication`
    اللي بتنزل للمكونات اللي تحت كـ props.
- **src/components/ApplicationForm.jsx**: الفورم. نفس الفورم بيشتغل للإضافة
  والتعديل: لو `initial` موجود يبقى تعديل، لو null يبقى إضافة. كل خانة
  ليها state خاصة (controlled inputs).
- **src/components/ApplicationList.jsx**: بيلف على القائمة بعد الفلترة
  ويعرض كارت لكل تقديمة، أو رسالة "مفيش حاجة هنا" لو فاضية.
- **src/components/ApplicationCard.jsx**: كارت تقديمة واحد: الشركة، الدور،
  اللينك، الحالة بلون مميز، تاريخ المتابعة، وزرارين Edit وDelete.
- **src/App.css**: كل التنسيق. لاحظ استخدام خصائص منطقية زي `text-align: end`
  عشان التصميم يفضل مظبوط لو النص عربي (RTL)، و`dir="auto"` في حقول النص
  عشان العربي يظهر من اليمين للشمال تلقائيًا.

## نشر المشروع على الإنترنت

### الطريقة الأسهل: Netlify

1. نفذ `npm run build` — هيتعمل فولدر اسمه `dist`.
2. افتح netlify.com واعمل حساب مجاني.
3. من لوحة التحكم اختار "Add new site" ثم "Deploy manually".
4. اسحب فولدر `dist` وارميه في الصفحة. خلاص، هيديك لينك شغال تحطه في الـ CV.

### GitHub Pages

1. في `vite.config.js` ضيف السطر ده جوا defineConfig:
   `base: '/اسم-الريبو/'` (مهم، وإلا الصفحة هتطلع فاضية).
2. اعمل `npm run build`.
3. ارفع المشروع على GitHub، ومن Settings ثم Pages اختار النشر من فولدر
   `dist` (أو استخدم حزمة gh-pages: `npm install -D gh-pages` وبعدين
   `npx gh-pages -d dist`).

## 5 أسئلة ممكن تتسأل عنها في المقابلة

1. **البيانات بتتحفظ فين وليه اخترت كده؟**
   في localStorage عشان المشروع لسه من غير backend. بستخدم `useEffect`
   بيحفظ القائمة كل ما تتغير، وبحملها أول ما التطبيق يفتح. الخطة إن ده
   يتبدل بـ API وقاعدة بيانات.
2. **إزاي التعديل شغال بنفس فورم الإضافة؟**
   لما تدوس Edit بخزن التقديمة في state اسمها `editing`، والفورم بيقراها
   كقيم مبدئية. عند الحفظ بنده `updateApplication` بدل `addApplication`.
3. **إيه فايدة الـ key في الـ map؟ وليه عملت key على الفورم نفسه؟**
   في القوائم React محتاج key ثابت عشان يعرف كل عنصر. على الفورم استخدمت
   `key={editing.id}` عشان لما أنتقل من تعديل تقديمة لتانية، React يعيد
   إنشاء الفورم بالقيم الجديدة بدل ما يفضل محتفظ بالقديمة.
4. **إزاي الفلترة شغالة؟**
   مبلمسش القائمة الأصلية. بحسب قائمة معروضة (`visibleApplications`)
   بالـ `filter` على حسب الحالة المختارة، فالفلترة فورية ومفيش بيانات بتضيع.
5. **لو عايز تضيف backend بعدين، إيه اللي هيتغير؟**
   مكان localStorage هنده API (مثلاً Express + قاعدة بيانات): الجلب يبقى
   في `useEffect` أول ما الصفحة تفتح، والإضافة/التعديل/المسح يبقوا requests
   للسيرفر. باقي المكونات مش هتحتاج تتغير كتير لأن الحالة متجمعة في App.
